# 活動・成果物抽出ツール — MVP仕様 v0.2

更新日: 2026-10-19

## 1. 目的とスコープ

高校の授業で生徒が編集・保存した Jupyter Notebook (`.ipynb`) から、先生が採点のために確認すべき学習活動の指示、回答、コード、保存された実行結果を取り出す。**Notebook中の Python 等は絶対にブラウザ上で実行しない。** ツールは GitHub Pages 上に静的ファイルとして公開し、読み込んだ提出物・正本をサーバへ送信せずブラウザ内で解析する。

- 機能名称は常に **「活動・成果物抽出」**。正本がある場合に同じ処理へ差分解析を追加する。
- 1回の処理は1種類の授業のNotebookを想定。
- 入力モード: (a) `.ipynb` 単一ファイル、(b) サブフォルダを含むフォルダから複数 `.ipynb` を一括取り込み。
- 正本（編集元 `.ipynb`）は別の入力欄から任意に指定。後から追加・解除できる。
- 抽出優先度: A=指定入力欄の成果物、B=追加セル（ある場合）、C=想定外の編集（補足）。
- 画面: ファイル別表示、活動別横断表示、確認が必要な判定を表示。先生は抽出結果の活動割当てを画面上で修正できる。
- 主出力: 元のファイル名に `_整理済み` を追加した `.ipynb`。フォルダ選択ではNotebookが1件でも元の相対パス階層を保持したZIPを返す。CSV/PDFによる採点・点数付与、外部ファイル再現は対象外。

## 2. 正本の有無で異なる保証

| 事象 | 正本なし | 正本あり |
| --- | --- | --- |
| 活動、指示、入力候補 | 教材の構造から抽出 | 構造＋正本から抽出 |
| 内容が初期状態から変更されたか | 確定不可 | 対応セル間で判定 |
| 新規・削除セルの確定 | 不可 | 可能な範囲で判定 |
| 正本と異なる教材 | 検出不可 | 見出し・ID・内容により不適合警告して差分停止 |
| 保存済み実行結果 | 保存されたものを表示 | 同じ |

「生徒が回答した」「未実施」と推測しない。表示語彙は「変更検出」「記入候補」「初期状態と同じ」「回答未検出」「要確認」「結果未保存」等とし、判断根拠を保持する。

## 3. 元教材から検証した構造ルール

根拠: 添付「ノートブックルール最新版ルール.ipynb」および「３次_6コマ_演習ノートブックQC版.ipynb」。

1. `#` はタイトル、`##` は章、`### 4-2. ワーク：...` のような番号＋活動ラベルは活動見出し。活動は次の同階層以上 (`###`, `##`) まで。
2. `---` が先頭にある Markdown セルと赤字 `＜入力＞` の組合せは記入欄の開始（同一セルにラベル）、次の `---` セルは通常記入欄の終了。 `---` 自体は活動の境界ではない。
3. 見出しと記入位置と実際に入力するセルは分離される。回答セルはMarkdownまたはコードで、複数になり得る。
4. `#### **プログラム例**`, `#### **プロンプト例**` は例示範囲。単独 `####` または次の例・活動で範囲終了する。例のコードは指定入力欄でない限り通常成果物から除外。
5. `<入力>` マーカーがない説明・サンプル・既存コードは原則成果物ではない（正本との差分があれば C 候補）。
6. `input()` の実行時入力は `.ipynb` に保存されていない場合復元不能。
7. `---` がコードフェンス、引用文、表中にある場合、入力欄の区切りと誤認しない。Markdown見出しもコードフェンス内部を除外する。

## 4. 解析処理

### 4.1 Notebook検証

`nbformat=4`、`cells` が配列であること、Markdown/codeセル、`source` の文字列または配列、outputsなどを検証。`metadata` や未対応 MIME は実行しない。破損したファイルは個別エラーとして処理継続。ファイル全体の処理上限を設ける。

### 4.2 活動・成果物の解析

- Markdownの見出しレベルと活動ラベル（復習/導入/解説/確認/実行/ワーク/共有）で活動範囲を構築。
- 活動本文から指示文の候補を抽出。見出し・サンプル・大量画像・コードは指示から外す。AIによる要約はしない。
- `＜入力＞` セルから開始し、次の正しい水平線セルまでを入力範囲とする。
- 未分類の追加セルが活動範囲内にある場合はその活動へ仮割当てし、根拠と曖昧さを記録。
- Markdown中の未入力の項目名 `項目名：`、`- 項目名：` やコードのコメントだけを回答完了とみなさない。

### 4.3 正本との照合

1. 教材適合性: 活動見出し一致・セルID一致・説明セル内容一致から判断。明らかな不適合時は差分解析を停止（成果物抽出自体は行う）。
2. マッチング: 唯一のセルID → 正規化した内容の完全一致 → 同一活動と前後アンカー位置を使った候補探索 → 局所的な文字列類似度。複数候補と一致度が低い候補は「要確認」。
3. 照合済セルの変更・移動・削除を判定。正本の入力欄マーカーが変更/削除された場合も、対応済みセルから元の活動・入力欄を復元する努力をする。
4. 同一ファイル中のセルID重複はIDだけで確定しない。整合しないセルは未分類へ残す。
5. 正本の解析結果は一括提出物全体で再利用する。

性能方針: セルIDと完全一致の索引作成は概ね O(N+M)。未対応セルのみ窓幅を制限して曖昧照合する。巨大なBase64・実行結果・画像は全文類似度計算しない。ファイル数 K に対し正本側の解析は1回。ブラウザUIを固めないよう処理ごとにイベントループへ処理を返す。

### 4.4 表示・保存結果

- 通常表示は活動単位で A, B を中心に表示。C は折りたたみの補足セクション。
- 解析結果を構造化してファイル別・活動別ビューを同じデータから生成する。
- 元のファイル名と相対パスが提出物の識別子。生徒名・番号を自動抽出せず、ファイル名の変更設定も持たない。画面には元ファイル名と相対パスを表示する。
- 原文セル番号/ID、正本照合の結果、抽出信頼度、保存済み出力（テキスト・画像）の存在を保持。
- 採点用Notebook先頭部はMarkdownで活動・元指示・回答・コード引用・保存済み出力を表示。コード引用は実行されない。
- 最後に「再実行用（原文のコードセル）」として提出物の全コードセルを元の順番でコピーする。`metadata.jupyter.source_hidden=true` などを付けるが、ブラウザごとに折りたたみ保証はない。コードは先生が手動実行するものとする。
- 画像出力は安全な PNG/JPEG に限り、Markdown attachment の形でレポートへ複製。実行結果内のHTMLやJavaScriptは動作させない。
- 生成されたNotebookはNotebook 4.x の仕様に従いセルIDを新しく割り振り、JSONとして保存。

### 4.5 ファイル名とフォルダ階層（v0.2）
- 単一ファイル：`生徒A.ipynb` → `生徒A_整理済み.ipynb`。
- フォルダ：`提出物/001/授業.ipynb` → ZIP内 `提出物/001/授業_整理済み.ipynb`。フォルダ名と階層は不変。
- ZIPダウンロード名は `整理済みNotebook一式.zip`。フォルダモードではNotebookが1件でもZIP。
- 非Notebookファイル、空フォルダは複製しない。生徒番号・氏名は自動判定せず、元名と相対パスを表示する。
- `webkitRelativePath`の相対階層を利用し、ZIPエントリ名の`/`を`_`に変更しない。絶対パス・`..`・`.`・空要素・制御文字は拒否し、重複した出力パスはエラーとして通知する。
- 元のNotebookは不変。生成したNotebookのメタデータには元の相対パスを保持する。

## 5. 非機能要件

- ファイル内容を送信しない。外部API、分析SDK、CDN読み込みを必要としない。配信時にWebアプリ自身の取得通信は発生する。
- 生徒が記入したHTMLはDOMへ直接挿入せず、画面はテキストとして表示。
- 生徒由来のNotebookコードはWebアプリでは実行しない。出力Notebookの再実行は先生が内容と依存関係を確認してから実施。
- 元ファイル不変。エラーはファイル単位に分離。
- 適度なデータサイズ上限、プログレス、エラーメッセージを設ける。
- 一括出力ZIPのファイル名にディレクトリトラバーサルを含めない。
- 処理対象の一括読み込みは1授業。異なる授業の提出物は適合性警告で区別。

## 6. 受入試験

T01 指定欄の記述変更、T02 入力範囲内に追加セル、T03 セル削除、T04 移動、T05 セルID総入替、T06 見出し変更、T07 複数候補、T08 例示コード編集(C)、T09 正本なし、T10 異なる授業の正本、T11 保存済みテキスト/画像出力、T12 フォルダ複数Notebook、T13 同名ファイルを別フォルダで区別、T14 実行コードとレポート分離、T15 元データ不変。

## 7. 明示した制約

- 文字通りの完全ロバストを保証しない（大規模書換、活動見出し・区切りをすべて除去、セル統合・分割、ID変更が重なると曖昧になる）。その場合は未分類/要確認に残す。
- Notebookをそのまま再実行できる保証はない。実行環境、依存ライブラリ、実行順序、対話入力、外部ファイルなどは別途必要。
- PDF、外部データファイル、成績記録・採点の入力はMVPから除外。
- HTML/CSVは将来拡張。MVPの一次出力は `.ipynb` のみ。フォルダ選択時は対象が1件でも `.zip` に格納し、選択したフォルダを起点とする階層を保持する。空フォルダや `.ipynb` 以外のファイルは出力しない。
